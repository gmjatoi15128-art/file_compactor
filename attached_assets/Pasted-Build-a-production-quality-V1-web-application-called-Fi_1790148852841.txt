Build a production-quality V1 web application called “File Compactor”.

IMPORTANT:
Do not build a generic file-tool clone.
Do not build 50+ tools.
Do not use fake compression or simulated results.
The core compression must actually work.

The product vision is:

“Simple, quality-focused file compression with generous free usage, transparent results, and privacy-conscious processing.”

The flagship tool is PDF compression. V1 should also include JPG, PNG, WebP, DOCX, PPTX and XLSX compression where technically reliable.

==================================================
1. PRODUCT PRINCIPLES
==================================================

The entire product must follow these principles:

1. Simple by default
2. Powerful when needed
3. Quality before aggressive compression
4. No misleading claims
5. Transparent results
6. Privacy-conscious
7. Generous free usage
8. No unnecessary signup
9. Clear errors
10. Verify generated files
11. Never silently corrupt or damage the original
12. Fast and responsive
13. Mobile-first responsive design
14. SEO-friendly architecture

The most important UX principle:

The user should not need to understand compression technology.

Instead of forcing users to choose DPI, JPEG quality, etc., first ask what result they want.

Example:

“What do you want?”

- Best quality
- Balanced
- Smallest possible
- Make it under a specific size

Advanced technical controls can exist under an “Advanced options” section.

==================================================

- scanned-page characteristics
- metadata

Do not overwhelm the user with technical information.

==================================================
10. PDF COMPRESSION ENGINE
==================================================

Implement REAL PDF compression.

Do not simulate compression.

The compression pipeline should attempt appropriate optimization in a quality-first order.

Possible stages:

1. Validate PDF
2. Analyze PDF
3. Optimize PDF structure
4. Remove safe unnecessary metadata where appropriate
5. Optimize embedded images
6. Apply selected quality/compression profile
7. Rebuild PDF
8. Validate generated PDF
9. Compare output size
10. Return verified result

Preserve wherever possible:

- page count
- page dimensions
- text
- vector graphics
- hyperlinks
- document structure

Do not blindly rasterize every page.

Do not convert text pages into images.

For scanned PDFs, use a scan-aware strategy.

If a file is already highly optimized:

Tell the user:

“This PDF is already highly optimized. We couldn't reduce it significantly without affecting quality.”

Do not force unnecessary compression.

==================================================
11. TARGET-SIZE ALGORITHM
==================================================

This is a core differentiating feature.

Example:

Original:
8.7 MB

Target:
2 MB

The system should progressively test appropriate compression strategies and select the best result that satisfies the target while preserving the highest practical quality.

Do NOT simply use the strongest compression setting.

If target cannot be reached safely:

Show:

“We couldn't reach 2 MB without significant quality reduction.”

Then:

“Best high-quality result: 2.8 MB”

Options:

“Use 2.8 MB”
“Try stronger compression”

Never silently destroy quality to hit a number.
